ATMOS ARRAY METERS
==================

Overview
--------

The Atmos Array replaces AP Pulse Nodes and provides a 2-2-5 air quality meter
stack under the left bottom rail. It consumes the core air cache:

    ~/.cache/gtex62-core/shared/air/<profile>/current.json

This cache is generated by the core air provider and merges:

- OpenWeather Air Pollution (fallback data + AQI category 1-5).
- AirNow concentrations via aq/data when enabled.
- AirNow AQI via aq/observation/latLong/current when enabled.

Per-pollutant source selection compares timestamps:

- AirNow is used for a pollutant when that pollutant's AirNow timestamp is no
  more than `AIRNOW_OWM_TOLERANCE` seconds older than the OpenWeather air
  snapshot.
- `AIRNOW_MAX_AGE` remains a hard ceiling so very old AirNow data is never used.
- Source markers under the labels follow this same per-pollutant decision.

Layout
------

2-2-5 meter configuration:

PRIMARY METERS (two-sided)
PM2.5 / O3   (AEROSOL)
PM1  / NO2  (OXIDANTS)

GAS ARRAY (5 columns, arrows only)
O3  NO2  SO2  CO  NH3

Units
-----

All values are normalized to ug/m3.

AirNow may return ppb/ppm for some gases; the fetch script converts to ug/m3:

O3  1 ppb ~= 1.96 ug/m3
NO2 1 ppb ~= 1.88 ug/m3
SO2 1 ppb ~= 2.62 ug/m3
CO  1 ppm ~= 1.145 mg/m3

AQI Indicator
-------------

An AQI square is drawn adjacent to the section title (To the right of ATMOS ARRAY). It uses AirNow AQI when fresh
(<= 1 hour old), otherwise it falls back to OpenWeather (AQI 1-5 mapped into
AirNow bands).

AirNow AQI color bands:

0-50    Good                          Green   (0,228,0)
51-100  Moderate                      Yellow  (255,255,0)
101-150 Unhealthy for Sensitive Groups Orange (255,126,0)
151-200 Unhealthy                     Red     (255,0,0)
201-300 Very Unhealthy                Purple  (143,63,151)
301-500 Hazardous                     Maroon  (126,0,35)

Source Markers
--------------

Small squares indicate the data source:

- Black = AirNow concentration value present.
- White = OpenWeather fallback.

Green Good Markers
------------------

Green vertical lines represent "good" thresholds. By default these come from
config/atmos_scales.env via the *_GREEN values. You can override per group in
theme.lua by defining good_values.

Gas Explanations
----------------

- PM2.5 (fine particulate matter, <= 2.5 microns): combustion (traffic, wildfire smoke, industry), high health relevance.
- PM10 (shown as PM1 label for spacing): coarser particles (dust, pollen, road dust), often weather dependent.
- O3 (ozone): formed by sunlight-driven reactions, respiratory irritant, rises on sunny afternoons.
- NO2 (nitrogen dioxide): combustion and traffic marker, indicates roadway and urban emissions.
- SO2 (sulfur dioxide): fossil fuel and industrial emissions, localized near point sources.
- CO (carbon monoxide): incomplete combustion (vehicles, heating), indicator for combustion pollution.
- NH3 (ammonia): agriculture and fertilizer emissions, contributes to secondary particle formation.

Theme Knobs (theme.lua)
-----------------------

Key sections for control:

- atmos_array.label (title layout).
- atmos_array.status (AirNow status square).
- atmos_array.aqi_indicator (AQI square size/position/colors).
- atmos_array.meters.style (shared meter styling).
- atmos_array.meters.pair1 / pair2 (range knobs, labels, offsets).
- atmos_array.meters.gas (per-gas range knobs, offsets, labels).
- atmos_array.meters.source_markers (per-pollutant source markers).

Indoor view (AirGradient)
-------------------------

Optional. When the suite binds the core `airgradient` domain, the POLLUTION table
alternates with an INDOOR table fed by an AirGradient ONE. OSA only draws what the engine
hands it: readings, scaling, the open/close-windows verdict and the alert text are all
computed in gtex62-core (see gtex62-core/docs/airgradient-provider-design.md and
ventilation-advisor-design.md). OSA reads

    ~/.cache/gtex62-core/shared/airgradient/<profile>/status.json

through `lua/suite/env.lua`; the profile is `airgradient = "<profile>"` under [profiles] in
~/.config/gtex62-core/suites/osa.toml. Without that binding, or with the domain disabled, nothing
changes: the panel never leaves the outdoor view.

Rotation (clock-driven, no stored state; defaults shown, all adjustable in the knobs below):

- Normally 15 s outdoor, then 15 s indoor, in a 30 s cycle.
- While an alert is visible: 10 s outdoor, 20 s indoor.
- Outdoor view only if the reading is older than 3 minutes or the provider is disabled or in error.

Indoor table (same seven rows as the outdoor POLLUTION table, with the (V) column and two trend columns; the header reads
`INDOOR // <LABEL>` when that fits in 12 characters and `INDOOR` alone when it does not, since the name is also on the SRC
line, `SRC // AG <LABEL>`):

| Row | Label | Value |
| --- | --- | --- |
| 1 | CO2 (PPM) | ppm, a whole number (482 shows 482, 1,150 shows 1,150) |
| 2 | PM 2.5 | ug/m3 (humidity-compensated, as Home Assistant shows it) |
| 3 | PM 10 | ug/m3 |
| 4 | PM 1 | ug/m3 |
| 5 | PM 0.3 (/DL) | particles/dL, a whole number (3,389 shows 3,389) |
| 6 | VOC INDEX | index |
| 7 | NOX INDEX | index |

The outdoor POLLUTION rows use the same short names (PM 2.5, OZONE, PM 10, NO2, SO2, CO, NH3).

**The (V) column** is right-aligned and shows each value as its source reports it, in at most five characters, for
the outdoor POLLUTION and POLLEN rows as well: two decimals under 100 (`5.27`, `12.34`), one decimal under 1,000
(`121.3`), a whole number with a thousands separator above (`1,107`), capped at `9,999`. CO2, PM0.3, the VOC and NOx
indexes and the pollen indexes are always whole numbers (a pollen index of 0 shows `0`, not `000`). A missing value shows
`---`. PM2.5 can read below PM1: only PM2.5 is humidity-compensated.

**The trend columns (1H and 24H)** on the pollution table show the change in each indoor reading over the last hour and
the last 24 hours, in whole percent with a sign (`+12%`, `-5%`, `0%`). The engine computes them (the `trend` block of the
AirGradient `status.json`, see gtex62-core's airgradient-provider-design.md): the last 10 minutes of readings against the
same 10 minutes an hour or a day earlier, `0%` when the change is under a per-metric noise floor, and `--` when there is
no comparison point yet (the provider was not running then; the 1H column is `--` for the first hour after a boot, and the
24H column is available at once because the provider seeds its history from its own input logs). The outdoor view shows the
same headers with blank cells, and the POLLEN table has only the name, bar and value columns.

With `[trend] use_ha_export = true` in the airgradient profile (gtex62-core), the provider fills the hour (or more) it was not
running from Home Assistant's history, so `1H` works minutes after a boot. While a number on screen was compared against that
history the indoor SRC line reads `SRC // AG CAVE | HA`; otherwise it is just `SRC // AG CAVE`.

**Widths** (`theme.env.atmos`): `table_value_w` 50 and two `table_trend_w` 46, taken out of the label column and the SOLAR
gauge (`solar_meter_w` 108, `solar_value_spread` 36, `meter_value_font_pt` 15, so a four-character UV or RAD such as `10.8`
or `1043` still sits clear of its bar); `table_value_align` is `"right"` (`"center"` is the old centered look). A theme
file from before 0.5.1 still draws cleanly (the value column widens to the widest value and the values right-align by
default), but copy these values into your `osa-theme.lua` to get the intended layout.

DATA line: the engine's alert text (29 characters or fewer, e.g. `OPEN WIN // CO2 1150 PPM`)
replaces `NOMINAL` in both views while an alert is visible; it never replaces an outdoor FAULT,
PARTIAL or STALE state. `AG STALE` replaces `NOMINAL` when the AirGradient reading is more than
3 minutes old. Alerts are hidden while the provider is in shadow mode (`[advisor] shadow = true` in
its profile), which is how it ships.

Event notices (gtex62-core's optional `[notices] enabled = true`): when no alert holds the line, a notice from the provider shows in
its place, in either view: `DATA // PM SPIKE // 2.5: 99` when PM2.5 jumps to at least 3 times its recent baseline (and up 10
ug/m3), `DATA // VOC SPIKE // 485` when VOC rises 150 over it. They state what was measured and never guess a cause. An advisor alert
takes the line first, and a notice that is still active shows again once the alert ends; an outdoor FAULT, PARTIAL or STALE state and
`AG STALE` outrank notices. More than one active notice takes turns every 10 seconds. Each lasts until the reading is back to
normal, and at most 60 minutes.

Theme knobs (`theme.env.airgradient` in theme/osa-theme.lua; omit any key for its default, shown below). The shipped theme
sets `enabled = false`, so set it to `true` as well as binding the domain in osa.toml. (With the whole block omitted
the code treats `enabled` as true.)
Values are validated and clamped, so a typo cannot break the panel. Restart conky after editing.

| Key | Default | Meaning |
| --- | --- | --- |
| enabled | true (shipped theme: false) | false: outdoor view only, no AirGradient alerts, no AG STALE |
| label | nil | name after the table title, e.g. `"CAVE"` (8 characters max, upper-cased); nil uses the provider profile's `label`, `""` shows no name |
| title | "INDOOR" | table title, 8 characters max; the name is added (`INDOOR // CAVE`) only when the whole header fits in 12 characters |
| source_tag | "AG" | tag on the SRC line, 6 characters max (`SRC // AG CAVE`) |
| cycle_sec | 30 | one outdoor + indoor rotation (2 to 3600) |
| outdoor_sec | 15 | outdoor share of the cycle (0 = indoor all the time) |
| alert_outdoor_sec | 10 | outdoor share while an alert is showing |
| stale_sec | 180 | a reading older than this gives the outdoor view (and AG STALE) |
| refresh_sec | 15 | how often status.json is re-read |
| show_alerts | true | engine advice on the DATA line |
| show_stale | true | AG STALE on the DATA line |
| show_notices | true | event notices on the DATA line when no alert holds it (`PM SPIKE // 2.5: 99`, `VOC SPIKE // 485`); add the key to your theme's block to set it, absent means true |

Tests: `tests/env_airgradient/run-tests.sh` (needs lua5.4 and jq; uses a scratch cache and a fake clock).
